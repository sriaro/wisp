# Wisp

A portable, single-exe Windows cleaner with an English and Chinese interface. Rust, Slint (femtovg renderer), liquid-glass look.

- Cleans junk files, finds stale registry entries, manages startup items and installed programs, maps disk usage, and offers a few Windows tweaks.
- Safety first: nothing is deleted until you confirm, registry fixes are backed up, and every optional recording feature (log, history, remembered settings, restore point, low-disk reminder) is off by default.
- Idle cost is zero: no background service, no timers while nothing happens.
- Adapts to the processor (`src/engine/cpu.rs`): scan threads follow the logical CPU count, hashing follows the fast physical cores, scans you wait for run below normal priority with high QoS, and background hashing runs in EcoQoS. Threads are never pinned, so Windows and the AMD and Intel drivers keep core placement.

## Build

Needs Windows 10/11 and Rust 1.99 or newer.

```
cargo build --release
```

The result is `target/release/Wisp.exe`, a single static executable.

To publish an exe, build with `tools/build-release.ps1` instead. It maps the project, Cargo and Rust folders to neutral names so the exe carries no local paths or user name.

## Test

```
target\release\Wisp.exe --selftest result.txt
```

The last line of `result.txt` must be `ALL PASS`. Close any running Wisp first; one check claims the single-instance lock.

`Wisp.exe --render <dir>` writes screenshots of every page; `PC_PREVIEW_ROOT` sets the folder the disk page scans, `PC_PREVIEW_ONLY` keeps only scenes whose name contains the text (for example `light-disk`), and `PC_PREVIEW_TICK` is the wait per scene in milliseconds.

## Layout

| Path | Contents |
| --- | --- |
| `src/engine/` | Cleaning, registry, startup, programs, backups, history, settings; no UI code |
| `src/pages/` | Page logic that feeds the Slint models |
| `src/app.rs`, `src/winui.rs` | App setup, scan/clean/fix flows, window handling, Win32 glue |
| `src/views.rs` | Builds the Slint list models from engine data, in-place model updates |
| `src/motion.rs` | Page transitions, theme crossfade, language fade-through |
| `src/i18n.rs`, `src/i18n_zh.rs` | English and Chinese text tables (every key must exist in both) |
| `src/selftest.rs`, `src/preview.rs` | `--selftest` checks and `--render <dir>` preview screenshots |
| `ui/` | Slint UI: `theme.slint`, `widgets.slint`, `motion.slint`, `main.slint`, `pages/` |
| `ui/icons/` | SVG icons generated by `tools/gen_icons.py` |
| `ui/art/` | Ring and shadow images generated by `tools/make-assets` |
| `assets/` | App icon and manifest |
| `third_party/femtovg/`, `third_party/i-slint-renderer-femtovg/` | Patched copies of the femtovg canvas and Slint's femtovg renderer (see `[patch.crates-io]` in `Cargo.toml` and `third_party/README.md`) |
| `tools/` | Asset generators and `build-release.ps1` |

## Regenerating assets

```
python tools/gen_icons.py
cd tools/make-assets && cargo run --release -- ../../assets ../../ui/art
```

## Data

Wisp keeps backups, settings, history and the log in a `data` folder next to `Wisp.exe` by default; the folder can be moved from the Backups page. The `data` folder is never part of the source tree.
